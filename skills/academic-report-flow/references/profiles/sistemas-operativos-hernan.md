## Delivery preferences

- Assignments usually arrive as instructions only.
- Use IEEE bibliography by default.
- Avoid language that is unnecessarily technical; explain clearly and academically.
- In `Antecedentes`, start by introducing the work:
  - `El presente ensayo trata...`
  - `El presente ensayo describe...`
  - `El presente informe analiza...`
- Demonstrate theory with graphs or comparative tables whenever useful.
- In `Descripción`, prioritize a clear conceptual map or synoptic chart when the topic can be expressed visually; this preference appears in the teacher's essay model and was reaffirmed by Alejandro on 2026-05-26.
- If the topic is short, two concrete conclusions are enough.
- Conclusions should be in third person, not first person.

## Mandatory alignment with unit slides

Before presenting any Sistemas Operativos assignment:

1. Review the available slide decks for the corresponding unit.
2. Check whether the assignment topic coincides with concepts, terminology, examples, classifications, or emphasis covered in those slides.
3. Validate that `Antecedentes`, `Descripción` and `Conclusiones` follow the same conceptual line taught by the instructor.
4. If external sources add depth, keep them consistent with the instructor's framing; explicitly flag any relevant difference or apparent contradiction before delivery.
5. If no slides for the topic/unit have been provided, request them or state that alignment against class material could not yet be validated.

The slides are an alignment reference for the teacher's approach; they do not replace proper citation of external academic sources when claims require support.

## Preferred visual execution

- Because the teacher's model prioritizes conceptual maps or synoptic charts for `Descripción`, prefer a wide mind-map layout when the topic has hierarchical relationships.
- Approved visual reference (Alejandro, 2026-05-26): `university/.reports-system/automation/academic-sources/sistemas-operativos/templates/visual-references/mapa-conceptual-editorial-aprobado-20260526.png`.
- Alejandro's preferred visual language: professional editorial canvas, central concept, curved hierarchical branches, restrained ink-like colors, human-feeling typography and brief explanatory leaf notes.
- Preserve readability over density: avoid filling leaf cards with paragraph-sized text that becomes illegible when inserted into an A4 report. If detailed explanation is necessary, distribute it across a second visual or the written body.
- Rejected visual anti-pattern (confirmed by Alejandro on 2026-05-26): do not produce rigid corporate-dashboard compositions with plain rectangular cards, excessive empty space, or a generic blue palette and call them conceptual-map style. The desired result must feel designed, organic and visually attractive, not merely ordered.
- The approved image is a style reference only; do not treat its example content as validated unit material without checking the corresponding slides.

## Recommended structure when only instructions are provided

Use the assignment wording first. If no explicit structure is given, prefer:

1. Tema
2. Antecedentes
   - introduce the work
   - contextualize importance
   - connect to operating systems
3. Desarrollo / Descripción
   - 2–4 subsections depending on scope
   - include at least one graph/table when theory benefits from comparison
4. Conclusiones
   - 2 concise third-person conclusions for short topics
   - 3 only when the topic has enough scope
5. Bibliografía
   - IEEE entries

## Style calibration

- Explain concepts without sounding like a processor manual.
- Prefer examples tied to OS behavior: processes, memory, scheduling, I/O, filesystems, virtualization, security.
- Use concrete comparisons over dense jargon.
